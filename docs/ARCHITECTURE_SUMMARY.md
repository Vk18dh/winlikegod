# FusionGuard AI - Architecture Summary

## 1. Project Goal
Develop an advanced RGB-Thermal pedestrian detection system for the Yugma TechFest 2.0 AI Hackathon that improves the baseline QFDet model. The objective is to enhance the detection of small and tiny pedestrians, particularly in poor illumination conditions, through adaptive multimodal fusion while maintaining real-time computational efficiency.

## 2. Folder Architecture
The project strictly enforces a highly organized directory structure to isolate dependencies and outputs:
- `configs/`: Configuration files (no hardcoded paths in code).
- `docs/`: Single source of truth for planning documents.
- `datasets/VTUAV_subset/`: Read-only dataset (RGB, Thermal, Annotations).
- `models/` & `weights/`: Source code and pretrained checkpoints.
- `scripts/`, `fusion/`, `evaluation/`, `visualization/`: Core execution modules.
- `results/`: Predictions, statistics, and graphs.
- `experiments/`: Isolated experiment runs (`EXP-001/`, `EXP-002/`).
- `reports/` & `logs/`: Autogenerated execution reports and execution logs.
- `tests/`: Automated unit tests.

## 3. Module Responsibilities
- **Dataset Loader & Validator**: Validates dataset integrity, pairs, and annotations without modifying source data.
- **Evaluation Pipeline**: Runs standard COCO metrics calculation on the QFDet model.
- **Fusion Module**: Contains experimental architectures for multimodal integration.
- **Benchmark Generator**: Automates FPS, latency, FLOPs, and mAP collection.
- **Report Generator**: Automatically builds markdown reports detailing experiment performance.

## 4. Dataset Workflow
1. **Load Image & Verify Pair**: Ensure 1:1 mapping between RGB and Thermal images.
2. **Read Annotation & Validate**: Verify COCO bounding boxes for pedestrians.
3. **Visualization & Statistics**: Generate scale distributions and side-by-side plots.
4. **Preprocessing**: Apply minimal necessary enhancements (e.g., CLAHE) dynamically.
5. **Inference**: Pass the validated, paired inputs into the model.

## 5. Evaluation Workflow
1. **Load Pretrained QFDet Checkpoint** (No training from scratch).
2. **Run RGB-only Inference** -> Extract metrics.
3. **Run Thermal-only Inference** -> Extract metrics.
4. **Run Fusion Baseline Inference** -> Extract metrics.
5. **Comparison**: Generate comprehensive quantitative (mAP, FPS) and qualitative (failure cases) reports.

## 6. Experiment Workflow
Every modification must follow the scientific experiment lifecycle:
- Created in an isolated `experiments/EXP-XXX/` directory.
- Copies configuration, runs training/evaluation, and saves weights.
- Generates metrics and visualizations.
- Concludes with a specific decision (Accepted, Needs Improvement, Rejected).
- Strictly compares against the baseline (RGB, Thermal, QFDet).

## 7. Coding Rules
- Pure Python 3.10+, PyTorch, and MMDetection.
- Strict adherence to PEP-8, type hints, and modular design.
- **No hardcoded paths**: Everything must be driven by configuration files.
- Produce detailed execution logs for all major operations.
- Generate automated markdown reports.
- Produce deterministic outputs.

## 8. Constraints
- **Do not train from scratch**; use provided QFDet pretrained weights.
- **Do not use external datasets**; limit to VTUAV-det subset.
- **Do not modify the dataset**; treat it as read-only.
- **Only target the Pedestrian class**.
- Do not overwrite previous experiment results or logs.

## 9. Quality Gates
Before progressing to any subsequent stage, the current stage must pass all gates:
- **Environment**: CUDA available, dependencies installed, baseline loads.
- **Dataset**: Zero missing pairs, no empty annotations.
- **Execution**: No runtime errors, predictions saved, logs created.
- **Evaluation**: Output metrics are reproducible and reports exist.
- **Stage Progression**: A complete Markdown report validates the stage (e.g., `STAGE2_COMPLETION_REPORT.md`).
